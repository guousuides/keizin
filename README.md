# 夏合宿 競馬企画

宴会中の6人競争に対して、参加者がスマホから馬券を買い、
オッズ・的中判定・払戻を全部自動計算する一式です。

春合宿版（`【サンプル】春合宿　競馬企画　計算用紙.xlsx`）を下敷きに、
**オッズを事前ポイント固定 → 実際の賭け金から算出** へ作り替えています。

## 2つの版があります。どちらか片方を使ってください

| | **① Webサイト版** → [`web/README.md`](web/README.md) | **② スプレッドシート版**（このファイル以下） |
|---|---|---|
| 動かし方 | `cd web && node server.js` だけ | 競人用スプシに Apps Script を貼る |
| 必要なもの | Node（入っているパソコン1台） | Googleアカウント・ドライブ |
| 準備時間 | 1分 | 15分 |
| 運営画面 | `/admin`（ログイン無し） | スプレッドシートのメニュー |
| 参加者 | 同じWi-Fiのスマホからブラウザで | 配ったURLから（Wi-Fi不問） |
| 記録 | `web/data/race.json` ＋ CSV書き出し | スプレッドシートにそのまま残る |

**計算式・オッズの考え方・注意点（三連系の期待払戻180%など）は両方とも同じです。**

- **その場のノリで動かしたい / ネットが不安 → ①Webサイト版**

## 導入手順（15分くらい）

1. **競人用スプレッドシートを開く**（1レース＝1ファイル。次のレースはファイルごとコピー）
2. 上部メニュー **拡張機能 → Apps Script**
3. 左のファイル一覧で、この `gas/` フォルダの4ファイルを作る
   （`.gs` は「スクリプト」、`Form.html` は「HTML」として追加）

   | 作るファイル名 | 中身をコピペする元 |
   |---|---|
   | `Config.gs` | `gas/Config.gs` |
   | `Setup.gs`  | `gas/Setup.gs` |
   | `WebApp.gs` | `gas/WebApp.gs` |
   | `Form`（HTML） | `gas/Form.html` |

   ※ 最初からある `コード.gs` は消してOK
4. 保存して、スプレッドシートを**リロード**
5. メニューに **🏇 競馬企画** が出るので **「① セットアップ」** を実行
   （初回だけ権限の確認が出ます。「詳細」→「安全でないページに移動」で承認）
6. **デプロイ → 新しいデプロイ → 種類「ウェブアプリ」**
   - 実行するユーザー：**自分**
   - アクセスできるユーザー：**全員**
   - → 出てきたURLを参加者に配る（メニュー「🔗 WebアプリのURLを表示」でも見られます）

> **「全員」にする理由**：参加者がGoogleアカウントでログインしなくても開けるようにするためです。
> URLを知っている人しか触れないので、当日その場で配る運用なら実質困りません。

## 計算の中身

### オッズ

各馬 `i` に賭けられた金額 `A_i` を、券種ごとに次のように積み上げます。

| 券種 | 配分 |
|---|---|
| 単勝 X に `m` pt | `A_X += m` |
| 複勝 X に `m` pt | `A_X += a·m` （`a` は設定シート、既定 `1/3`） |
| 三連単 X→Y→Z に `m` pt | `A_X += m/2`, `A_Y += m/3`, `A_Z += m/6` |
| 三連複 X,Y,Z に `m` pt | 3頭それぞれ `+= m/3` |

重みが必ず `1/2+1/3+1/6 = 1`、`1/3×3 = 1` になっているので、
**賭け金の総額 `T` = `ΣA_i`** がぴったり一致します（複勝だけ `a` 倍された額で入る）。

```
O_i = T / A_i
```

このとき `p_i := 1/O_i = A_i/ΣA_i` となり、6頭ぶん足すとちょうど `1`。
つまり `p_i` を「その馬が1着になる想定確率」としてそのまま扱えます。
（Pythonで実データ200件を流して `Σ(1/O_i) = 1.000000000000` を確認済み）

### 払戻

```
単勝   = 賭け金 × O_i
複勝   = 賭け金 × a × O_i
三連単 = 賭け金 × O_i × O_j × O_k
三連複 = 賭け金 × O_i × O_j × O_k ÷ 6
```

最後に `MEDIAN(オッズ下限, 値, オッズ上限)` で `1.1 〜 999` 倍に押し込み、
`CEILING(…, 丸め単位)` で切り上げます。

## ★ 事前に知っておいてほしい2つのクセ

数値検証した結果です。**バグではなく、この計算式の性質**です。

### ① 三連単・三連複は期待払戻が約180%

6頭が完全に横一線（`p = 1/6`）のとき:

|  | 的中確率 | 払戻倍率 | 期待払戻 |
|---|---|---|---|
| 三連単 | `3!/6! = 1/120` | `6×6×6 = 216` 倍 | **1.80** |
| 三連複 | `3!3!/6! = 1/20` | `216÷6 = 36` 倍 | **1.80** |

`O_i×O_j×O_k = 1/(p_i p_j p_k)` は「3回とも独立に引き直す」計算になっていて、
1着に決まった馬は2着になれない（＝残りの母数が減る）ぶんを織り込めていないためです。

しかも倍率は固定ではなく、**買う馬によって 1.46 〜 2.44 倍と揺れます**
（人気馬で固めるほど大きくなる）。なので一律の係数では完全には均せません。

**対処（好きなものを）**
- **(a) 何もしない** — 派手な配当が出て盛り上がる。企画としてはこれもアリ
- **(b) 設定シートの「三連単係数」「三連複係数」を 0.5〜0.6 に下げる** — 手っ取り早い
- **(c) 設定シートの「三連系方式」を「Harville補正」にする** —
  `1着 p_i → 2着 p_j/(1-p_i) → 3着 p_k/(1-p_i-p_j)` と正しく条件付けした確率の逆数を使う。
  **期待払戻がちょうど100%になることを検証済み**（不均一な人気3ケースで全て `1.0000`）

### ② 複勝は「穴馬買い」が数学的に得

`a = 1/3` で100%還元になるのは横一線のときちょうど、です。人気が偏るとズレます。

| `p_i` | 3着以内率 | 複勝の期待払戻 |
|---|---|---|
| 0.167 | 50.0% | **100%** ← 横一線 |
| 0.357 | 81.8% | 76% ← 本命 |
| 0.500 | 91.7% | 61% ← 大本命 |
| 0.100 | 41.7% | 139% ← 穴 |
| 0.040 | 40.1% | **334%** ← 大穴 |

3着以内率は100%で頭打ちなのに `a × O_i` は `p` が小さいほど青天井に伸びるため。
**大穴に賭ける動機ができるので、企画としてはむしろ健全**だと思います。
気になるなら「控除率」を上げてください。

## 春合宿版から直したバグ

| 場所 | 内容 |
|---|---|
| `①〜⑥の計算式!B17` | 三連複の6項目のうち最終項の分母が `(1-H-G)` でなく `(1-G-F)` → 実データで検算すると**オッズが約15%低く出ていた** |
| `J25 / M25 / P25` | 三連複の第1項で除算 `/` が乗算 `*` になっていた |
| `①の計算式!C10` | `='仮オッズ'!D9:D18` という意図不明の残骸 |
| `A馬券購入!G3` ほか | `COUNTIF('仮オッズ'!$A$17:$B$22,"未選択")` がラベル列まで含んでいた（`$B$17:$B$22` が正） |
| 構造 | 参加者ごとに計算式シートが12枚 → 購入ログ1枚＋精算1枚に集約 |

## 変えたくなったら

| やりたいこと | どこを触る |
|---|---|
| 係数・持ち点・受付状態 | **設定シートのB列**（スクリプト不要） |
| 出走人数を6人から変える | `Config.gs` の `HORSE_COUNT` → セットアップ再実行 |
| チーム数を10から変える | `Config.gs` の `TEAM_COUNT` → セットアップ再実行 |
| 購入本数の上限（既定300） | `Config.gs` の `BET_ROWS` → セットアップ再実行 |

セットアップは何回流しても、**出走馬名・チーム名・設定値・購入ログ・結果は退避して書き戻す**
ので消えません。安心して再実行してください。

> ⚠️ 払戻の計算式そのものを変えるときは、**シート側（`Setup.gs` の精算シート）と
> Webアプリのオッズ表示（`Form.html` の `oddsFor()`）の両方**を直してください。
> フォームの表示はシートの計算を写しているだけなので、片方だけ変えると食い違います。
