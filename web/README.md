# 夏合宿 競馬企画 — ローカルWebサイト版

スプレッドシート＋Apps Script 版（`../gas/`）と同じ企画を、
**パソコン1台で動くWebサイト**にしたものです。Googleアカウントもドライブも要りません。

- **参加者ページ** `/` … チームを選んで馬券を買う。オッズが実況で動く
- **運営ページ** `/admin` … 出走馬・チーム・設定・受付開始/締切・着順入力・精算・CSV書き出し

ログインはありません。運営ページはURLの末尾に `/admin` を付ければ開けます。

---

## 使い方

```
cd web
node server.js
```

これだけ。`npm install` も外部ライブラリも不要です（Node だけで動きます）。

起動するとターミナルにURLが出ます。

```
  参加者ページ  http://localhost:3000/
  運営ページ    http://localhost:3000/admin

  同じWi-Fiのスマホからは ↓ を配ってください
      http://192.168.x.x:3000/
```

**参加者のスマホから開くときは、その `192.168.…` の方を配ってください。**
`localhost` はサーバを動かしているパソコン自身しか開けません。
同じWi-Fiに全員つながっていることが条件です。

ポートを変えたいときは `PORT=8080 node server.js`。

## 当日の流れ

| いつ | 誰が | やること |
|---|---|---|
| 事前 | 運営 | `/admin` の **②出走馬・チーム** で6人と各チーム名を入れる |
| 事前 | 運営 | **③設定** で持ち点・複勝係数・三連系方式を確認（下の「決めておくこと」参照） |
| 宴会前 | 運営 | **①進行** →「▶ 受付を開始する」／スマホ用URLを配る |
| 受付中 | 参加者 | `/` でチームを選んで購入。オッズは賭けが入るたびに動く |
| レース直前 | 運営 | **①進行** →「⏹ 受付を締め切る」← **これでオッズ確定** |
| レース後 | 運営 | **①進行** の「着順を入れる」で1〜3着を選んで保存 |
| 発表 | 全員 | **⑥順位** に収支と順位。参加者の画面にも自動で出る |
| 次のレース | 運営 | **①進行** →「リセット」（出走馬・チーム・設定は残る） |

## 出走馬（代表者6人）の登録

1. `http://localhost:3000/admin` を開く
2. 上のタブで **②出走馬・チーム** を選ぶ
3. 「出走馬（代表者）」の1〜6行に名前を入れる
   - 右側の「ひとこと（任意）」は参加者のオッズ表に小さく出る（「腕相撲最強」とか）。空でよい
   - 7人以上にしたいときは **＋ 1人 増やす**
   - 名前を空のままにした行は「出走しなかった」扱いになり、参加者の選択肢から消える
4. **「出走馬を保存する」を押す** ← これを押すまで反映されない
5. 同じ画面の下でチーム名も入れて「チームを保存する」

入力を触ると **● 未保存** の印が出ます。出ているあいだは保存されていないので、
必ず保存ボタンを押してください（印が出ているあいだ、3秒ごとの自動更新は
そのフォームに触らないので、打ちかけが消えることはありません）。

**受付を開始したあとに名前を変えるのは避けてください。**
既に買われた馬券の指名が今の出走馬に無い名前になり、その馬券が集計から外れます
（保存時に警告が出ます）。

## 決めておくこと（③設定）

| 項目 | 既定 | ひとこと |
|---|---|---|
| 複勝係数 a | 1/3 ≒ 0.3333 | このままで複勝の期待払戻がちょうど100% |
| 控除率 | 0 | 胴元の取り分。0なら全額還元 |
| オッズ下限 / 上限 | 1.1 / 999 | 元返し防止と、0票の馬でオッズが飛ぶのを防ぐ天井 |
| 三連単係数 / 三連複係数 | 1 / 1 | ↓の注意を読んでから決める |
| 初期持ち点 | 1000 | 各チームに配るpt |
| 丸め単位 | 1 | 5にすると5pt刻みで切り上げ |
| **三連系方式** | 単純積 | ↓の注意を読んでから決める |

### ⚠ 三連単・三連複は「単純積」だと期待払戻が約180%

6人が完全に横一線（p = 1/6）のとき——

|  | 当たる確率 | 倍率 | 期待払戻 |
|---|---|---|---|
| 三連単 | `3!/6! = 1/120` | `6×6×6 = 216`倍 | **1.80** |
| 三連複 | `3!3!/6! = 1/20` | `216÷6 = 36`倍 | **1.80** |

`O_i×O_j×O_k = 1/(p_i p_j p_k)` は「3回とも6人から引き直す」計算になっていて、
1着に決まった人は2着になれない（＝残りの母数が減る）ぶんを織り込めていないためです。
しかも倍率は固定ではなく、**買い目によって 1.35〜3.09倍と揺れます**（人気を集めた人で固めるほど大きい）。

**対処（好きなものを）**

- **(a) 何もしない** — 派手な配当が出て盛り上がる。企画としてはこれもアリ
- **(b) 三連単係数・三連複係数を 0.5〜0.6 に下げる** — 手っ取り早い
- **(c) 三連系方式を「Harville補正」にする** —
  `1着 p_i → 2着 p_j/(1−p_i) → 3着 p_k/(1−p_i−p_j)` と正しく条件付けした確率の逆数を使う。
  **全買い目で期待払戻がちょうど1.000になることを検証済み**

### ⚠ 複勝は「穴馬買い」が数学的に得

`a = 1/3` で100%還元になるのは6人が横一線のときちょうど、です。人気が偏るとズレます。

| その人の p | 3着以内率 | 複勝の期待払戻 |
|---|---|---|
| 0.50（大本命） | 91.7% | 61% |
| 0.167（横一線） | 50.0% | **100%** |
| 0.04（大穴） | 40.1% | **334%** |

3着以内率は100%で頭打ちなのに `a × O_i` は p が小さいほど伸び続けるためです。
大穴に賭ける動機ができるので、企画としてはむしろ健全だと思います。
気になるなら控除率を上げてください。

## ファイルの役割

| ファイル | 中身 | 触る？ |
|---|---|---|
| `server.js` | 保存と受付のルール（締切判定・持ち点チェックなど） | 基本触らない |
| **`engine.js`** | **オッズと払戻の計算。★式はここにしか無い** | 式を変えるならここだけ |
| `public/index.html` `app.js` | 参加者ページ | |
| `public/admin.html` `admin.js` | 運営ページ | |
| `public/style.css` | 見た目 | |
| `data/race.json` | 今のレースの全データ（自動生成） | 触らない |
| `data/archive/` | リセット時に退避された過去レース | 見返す用 |

`engine.js` はサーバとブラウザの両方が読み込みます。
なので **「画面に出ている想定オッズ」と「実際に精算される払戻」が食い違うことは原理的に起きません。**
（Apps Script版はシート側とフォーム側で式が二重管理になっていたので、そこを1本化しています）

## 計算の中身

### オッズ

各人 `i` に集まった金額 `A_i` を、券種ごとに次のように積み上げます。

| 券種 | 配分 |
|---|---|
| 単勝 X に `m` pt | `A_X += m` |
| 複勝 X に `m` pt | `A_X += a·m` |
| 三連単 X→Y→Z に `m` pt | `A_X += m/2`, `A_Y += m/3`, `A_Z += m/6` |
| 三連複 X,Y,Z に `m` pt | 3人それぞれ `+= m/3` |

重みが必ず `1/2+1/3+1/6 = 1`、`1/3×3 = 1` になっているので、
配分しても金額は増えも減りもしません。だから **`ΣA_i` がそのまま賭け金の総額**です。

```
T   = ΣA_i × (1 − 控除率)      払戻に回る総額
O_i = T ÷ A_i                  素オッズ
p_i = A_i ÷ ΣA_i               想定1着率（6人ぶん足すとちょうど1）
```

### 払戻

```
単勝   = 賭け金 × O_i
複勝   = 賭け金 × a × O_i
三連単 = 賭け金 × O_i × O_j × O_k          （単純積のとき）
三連複 = 賭け金 × O_i × O_j × O_k ÷ 6      （単純積のとき）
```

最後に `下限 〜 上限` に押し込んでから、丸め単位で切り上げます。

## 検証済みのこと

| 内容 | 結果 |
|---|---|
| 手書きの例（A100万 B50万 …）のオッズ | 2.50 / 5.00 / 6.25 / 10.00 / 12.50 / 16.67 と一致 |
| `Σ(1/O_i) = 1` | `1.000000000000`（0票の人はオッズ上限で頭打ちになるので、その人だけ例外） |
| `Σp_i = 1` | `1.000000000000`（0票の人が居ても成立） |
| Harville補正の期待払戻 | 全買い目で `1.000`（人気が偏った3ケースでも） |
| 単純積の期待払戻 | 横一線で `1.800`、偏ると `1.35〜3.09` に揺れる |
| 不正な購入（重複指名・持ち点オーバー・小数pt・締切後 など） | 9パターンすべて拒否 |
| 的中判定（単勝・複勝・三連単・三連複） | 全券種で正しく判定 |
| 10チームが150リクエスト同時 | 取りこぼし0件・持ち点オーバー0件・ID重複0件（453ms） |
| 運営ページで6人ぶん打ち込んで自動更新3回ぶん放置 | 消えない（未保存印が出ているフォームは自動更新が触らない） |

## 困ったとき

| 症状 | 対処 |
|---|---|
| スマホから開けない | 同じWi-Fiか確認。パソコンのファイアウォールでNodeを許可する |
| 起動時に `EADDRINUSE` | ポートが使用中。`PORT=3001 node server.js` |
| データを消してしまった | `data/archive/` に過去レースが残っています |
| `保存できませんでした` の警告 | ウイルス対策ソフトがファイルを掴んでいる。進行は続くので、終わる前に運営ページでCSVを書き出してください |
| オッズを全部やり直したい | 運営ページ「リセット」（退避されるので消えません） |

サーバを止めるのはターミナルで `Ctrl+C`。
購入内容は `data/race.json` に都度保存しているので、止めても消えません。
