# 夏合宿 競馬企画 — ローカルWebサイト版

スプレッドシート＋Apps Script 版（`../gas/`）と同じ企画を、
**パソコン1台で動くWebサイト**にしたものです。Googleアカウントもドライブも要りません。

- **参加者ページ** `/` … チームを選んで馬券を買う。オッズが実況で動く
- **オッズ画面（スクリーン用）** `/odds` … 当日会場のスクリーン・プロジェクターに大きく映す専用オッズ表
- **運営ページ** `/admin` … 出走馬・チーム・設定・受付開始/締切・着順入力・精算・CSV書き出し

**持ち点はレースをまたいで引き継がれます。**
当たった払戻ぶんも次のレースで賭けられるので、何レースやっても通算で競えます
（→「[持ち点はレースをまたいで引き継がれます](#持ち点はレースをまたいで引き継がれます)」）。

ログインはありません。運営ページはURLの末尾に `/admin` を付ければ開けます。

---

## 使い方

```
cd web
node server.js
```

これだけ。`npm install` も外部ライブラリも不要です（Node だけで動きます）。

起動するとターミナルにURLが出ます。

```
  参加者ページ  http://localhost:3000/
  オッズ画面    http://localhost:3000/odds  （スクリーン投影用）
  運営ページ    http://localhost:3000/admin

  同じWi-Fiのスマホからは ↓ を配ってください
      http://192.168.x.x:3000/

  会場のスクリーン・プロジェクター用:
      http://192.168.x.x:3000/odds
```

**参加者のスマホから開くときは、その `192.168.…` の方を配ってください。**
`localhost` はサーバを動かしているパソコン自身しか開けません。
同じWi-Fiに全員つながっていることが条件です。

ポートを変えたいときは `PORT=8080 node server.js`。

## Vercel に置く場合（★KVの設定が必須です）

会場のWi-Fiが不安、参加者が別々の回線から入る、といったときは Vercel に置けます。
ただし **Upstash / Vercel KV の設定を省くと確実に壊れます。**

### なぜ必須なのか

Vercel は1台のサーバではなく、リクエストごとに別のインスタンスが応答します。
インスタンスどうしはメモリも `/tmp` も共有しません。つまり保存先を用意しないと——

- 運営が「受付を開始」を押す → **そのとき応答したインスタンスだけ** が受付中になる
- 参加者ページは3秒ごとに自動更新 → どのインスタンスに当たるかは毎回バラバラ
- 結果、**「受付中」と「締切」が数秒おきに入れ替わり、買えたり買えなかったりする**
- 購入もインスタンスごとにバラバラに溜まり、消えたように見える

KVを設定すると、書き換えのたびに全インスタンス共通の保存先へ書き戻すので、これが起きません。

### 手順（所要10分・無料・クレジットカード不要）

Vercelの画面から Storage を作れないことがあります（プランや時期でメニューが変わります）。
その場合は **Upstash に直接登録して、環境変数だけ手で入れれば同じです。**
以下は Vercel の Storage メニューを一切使わない手順です。

#### ① Upstash で保存先を作る

1. <https://console.upstash.com> を開き、GitHubアカウントかメールで **Sign up**
2. 上のタブで **Redis** を選び、**Create Database**
3. 入力するのは3つだけ

   | 項目 | 選ぶもの |
   |---|---|
   | Name | `keiba` など何でもよい |
   | Primary Region | **Japan (Tokyo)**（会場が日本なら。速さだけの話） |
   | Type | **Free / Regional**（無料枠。企画1回なら余裕で足ります） |

4. **Create** を押すと、データベースの詳細画面が開きます

#### ② URLとトークンを控える

詳細画面を下にスクロールすると **REST API** という欄があります。
そこの2行をコピーしてください（`Redis` タブではなく **`REST API`** の方です）。

```
UPSTASH_REDIS_REST_URL   https://xxxx-yyyy-12345.upstash.io
UPSTASH_REDIS_REST_TOKEN AXxxAAIjcDE...（長い文字列）
```

> トークンはパスワードと同じです。人に見せたりGitHubに上げたりしないでください。

#### ③ Vercel に環境変数として入れる

1. Vercel でこのプロジェクトを開く
2. **Settings** → 左メニューの **Environment Variables**
3. 次の2つを追加する（Key と Value を貼って **Save**、をそれぞれ1回ずつ）

   | Key | Value |
   |---|---|
   | `KV_REST_API_URL` | ②でコピーした `https://xxxx.upstash.io` |
   | `KV_REST_API_TOKEN` | ②でコピーした長いトークン |

   Environment の選択欄は **Production / Preview / Development の3つ全部にチェック** を入れてください。

   > `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN` という名前のままでも動きます
   > （`server.js` が両方の名前を見ています）。Upstashの画面からコピーした名前をそのまま使ってもOKです。

#### ④ 再デプロイする（★これを忘れると反映されません）

環境変数は**追加しただけでは効きません。**

1. **Deployments** タブを開く
2. 一番上のデプロイの右端 **⋯** → **Redeploy**
3. `Use existing Build Cache` のチェックを外して **Redeploy**

#### ⑤ 確認する

運営ページ（`/admin`）を開いて、**一番上に赤い帯が出ていなければ設定できています。**

赤い帯が出ている場合は、そこに理由が書いてあります。

| 赤帯の内容 | 対処 |
|---|---|
| 「クラウドKVが未設定です」 | ③の環境変数が入っていない、または④の再デプロイをしていない |
| 「通信に失敗しています」 | URLかトークンの貼り間違い。②からコピーし直す（前後の空白に注意） |

仕上げの確認として、**スマホとパソコンの2台で参加者ページを開き、運営ページで受付を開始→締切**を
何度か切り替えてみてください。2台とも同時に切り替われば直っています。

**赤帯が出ている状態で本番に入らないでください。** 上に書いた症状がそのまま起きます。

| いつ | 誰が | やること |
|---|---|---|
| 事前 | 運営 | `/admin` の **②出走馬・チーム** で6人と各チーム名を入れる |
| 事前 | 運営 | **③設定** で持ち点・複勝係数・三連系方式を確認（下の「決めておくこと」参照） |

| 次のレース | 運営 | **①進行** →「次のレースへ」← **ここで持ち点が繰り越される**（出走馬・チーム・設定も残る） |

## オッズは受付中は伏せてあります

**受付中にオッズが見えると、後から買う人ほど有利になります**（人気薄を狙い撃ちできる）。
そうすると全員が締切間際まで買い控えるので、既定では伏せてあります。
**締切を押した瞬間に一斉開示**されるので、スクリーンでの見せ場も作れます。

伏せているのは **サーバ側**（`publicState()` の `maskHorses`）です。
倍率だけでなく `pool`（各馬の投票pt A_i）と `totals` も参加者のブラウザに送っていません。
`オッズ = T ÷ A_i` なので、A_i を残すと開発者ツールで復元できてしまうためです。
自分が買った馬券の倍率（`myBets[].odds`）も、そこから支持率が逆算できるので伏せます。
「何点買われたか」（`betCount`）だけは出します — 件数からどの馬が人気かは分からないので。

**運営ページは受付中でも常に全部見えます。**

### 切り替えかた（2か所）

| どこ | 何を決めるか |
|---|---|
| **③設定**「受付中はオッズを隠す」 | ふだんの動き。ONで受付中は伏せる（既定）。OFFにすると従来どおり常時公開 |
| **①進行**「オッズの開示」 | いまこの瞬間の上書き。タイミングをその場でずらしたいとき |

①進行のボタンは3つです。

- **👁 いま開示する** … 受付中でも倍率を出す
- **🙈 いま伏せる** … 締切を押しても出さない。スクリーンで溜めてから見せたいとき
- **↩ 自動にまかせる** … ③設定どおりに戻す（既定）

カードの下に「いま：非開示（自動：受付中のため。締切を押すと一斉開示されます）」のように
**現在の状態と理由**が出るので、どちらが効いているか迷いません。
上のKPI欄とページ見出しのバッジでも確認できます。

### 覚えておくこと

- **着順を3つ入れると、どの指定でも必ず開示されます。**
  払戻ptを出す時点で `払戻 ÷ 賭けpt` から倍率が分かるので、隠す意味が無くなるためです。
- **受付を開始すると①進行の指定は「自動」に戻ります。**
  前のレースで「いま開示する」を押したままだと、次のレースが最初から丸見えで始まってしまうためです。
- 「次のレースへ」「全部リセット」「全消去」でも「自動」に戻ります。

## 持ち点はレースをまたいで引き継がれます

2レース目以降、各チームは **前のレースを終えた時点の残高** で始めます。

```
このレースの持ち点（開始pt） = 前のレースの残高
                             = 前のレースの開始pt − 使用pt + 払戻pt
```

**当たった払戻ぶんもそのまま次のレースで賭けられます。**
勝ち続ければ持ち点は増えていき、溶かせば減ります。
繰り越しているので **「残高」がそのまま通算成績** です（別に集計する必要はありません）。

| どこで見えるか | 何が出るか |
|---|---|
| 参加者 `/` の持ち点カード | このレースの持ち点と、繰越であることの注記 |
| 参加者 `/` の「このチームのこれまで」 | 各レースの開始pt → 終了時ptの推移 |
| 運営 **⑥順位** | 開始pt・収支・残高（次に持ち込む額） |
| 運営 **⑥順位** の「通算」 | レースごとの残高の推移。CSVでも書き出せる |

### 繰り越されるタイミング

**①進行 →「次のレースへ」を押した瞬間だけ**です。着順を入れただけでは繰り越されません
（まだそのレースの精算表示にすぎない）。

- **着順が入っている状態で押した** → 精算した残高を次のレースの持ち点にする
- **着順が空のまま押した** → **繰り越さない**。そのレースを無かったこと（賭け金は返却）にして
  持ち点を据え置く。レースが中止になったときはこれで正しい
  （そのまま精算すると全馬券が「不的中」になり、全員が賭けたぶんだけ損してしまうので）

### 全部溶かしたチームの扱い

残高が0になると以降なにも買えず、企画から脱落してしまいます。
それを避けたいときは ③設定の **「敗者復活の最低持ち点」** を 100 などにしておいてください。
繰り越すときにその額まで戻します（既定は0＝復活なし）。

### 持ち点を手で直したいとき

①進行の **「チームの持ち点（繰越）」** で各チームの開始ptを直接書き換えられます。
着順を入れ間違えて精算してしまった等の救済用で、ふだんは触る必要がありません。
同じ場所の **「全部リセット」** は繰越と全レースの履歴を消して1レース目に戻します（企画のやり直し用）。

> **注意** 繰越はチーム名をキーにして覚えています。
> 途中でチーム名を変えると別チーム扱いになって繰越が引き継がれず、初期持ち点に戻ります。
> 途中から増えたチームも初期持ち点で始まるので、必要なら上記の画面で調整してください。

## 出走馬（代表者6人）の登録

1. `http://localhost:3000/admin` を開く
2. 上のタブで **②出走馬・チーム** を選ぶ
3. 「出走馬（代表者）」の1〜6行に名前を入れる
   - 右側の「ひとこと（任意）」は参加者のオッズ表に小さく出る（「腕相撲最強」とか）。空でよい
   - 7人以上にしたいときは **＋ 1人 増やす**
   - 名前を空のままにした行は「出走しなかった」扱いになり、参加者の選択肢から消える
4. **「出走馬を保存する」を押す** ← これを押すまで反映されない
5. 同じ画面の下でチーム名も入れて「チームを保存する」

入力を触ると **● 未保存** の印が出ます。出ているあいだは保存されていないので、
必ず保存ボタンを押してください（印が出ているあいだ、3秒ごとの自動更新は
そのフォームに触らないので、打ちかけが消えることはありません）。

**受付を開始したあとに名前を変えるのは避けてください。**
既に買われた馬券の指名が今の出走馬に無い名前になり、その馬券が集計から外れます
（保存時に警告が出ます）。

## 決めておくこと（③設定）

| 項目 | 既定 | ひとこと |
|---|---|---|
| 複勝係数 a | 1/3 ≒ 0.3333 | このままで複勝の期待払戻がちょうど100% |
| 控除率 | 0 | 胴元の取り分。0なら全額還元 |
| オッズ下限 / 上限 | 1.1 / 999 | 元返し防止と、0票の馬でオッズが飛ぶのを防ぐ天井 |
| 三連単係数 / 三連複係数 | 1 / 1 | ↓の注意を読んでから決める |
| 初期持ち点 | 1000 | 1レース目に配るpt。2レース目以降は前のレースの残高を繰り越すので、途中で変えても既存チームには影響しない |
| 敗者復活の最低持ち点 | 0 | 繰越の下限。100などにすると0になったチームも次のレースで復帰できる |
| 丸め単位 | 1 | 5にすると5pt刻みで切り上げ |
| **三連系方式** | 単純積 | ↓の注意を読んでから決める |

### ⚠ 三連単・三連複は「単純積」だと期待払戻が約180%

6人が完全に横一線（p = 1/6）のとき——

|  | 当たる確率 | 倍率 | 期待払戻 |
|---|---|---|---|
| 三連単 | `3!/6! = 1/120` | `6×6×6 = 216`倍 | **1.80** |
| 三連複 | `3!3!/6! = 1/20` | `216÷6 = 36`倍 | **1.80** |

`O_i×O_j×O_k = 1/(p_i p_j p_k)` は「3回とも6人から引き直す」計算になっていて、
1着に決まった人は2着になれない（＝残りの母数が減る）ぶんを織り込めていないためです。
しかも倍率は固定ではなく、**買い目によって 1.35〜3.09倍と揺れます**（人気を集めた人で固めるほど大きい）。

**対処（好きなものを）**

- **(a) 何もしない** — 派手な配当が出て盛り上がる。企画としてはこれもアリ
- **(b) 三連単係数・三連複係数を 0.5〜0.6 に下げる** — 手っ取り早い
- **(c) 三連系方式を「Harville補正」にする** —
  `1着 p_i → 2着 p_j/(1−p_i) → 3着 p_k/(1−p_i−p_j)` と正しく条件付けした確率の逆数を使う。
  **全買い目で期待払戻がちょうど1.000になることを検証済み**

### ⚠ 複勝は「穴馬買い」が数学的に得

`a = 1/3` で100%還元になるのは6人が横一線のときちょうど、です。人気が偏るとズレます。

| その人の p | 3着以内率 | 複勝の期待払戻 |
|---|---|---|
| 0.50（大本命） | 91.7% | 61% |
| 0.167（横一線） | 50.0% | **100%** |
| 0.04（大穴） | 40.1% | **334%** |

3着以内率は100%で頭打ちなのに `a × O_i` は p が小さいほど伸び続けるためです。
大穴に賭ける動機ができるので、企画としてはむしろ健全だと思います。
気になるなら控除率を上げてください。

（Apps Script版はシート側とフォーム側で式が二重管理になっていたので、そこを1本化しています）

## 計算の中身

### オッズ

各人 `i` に集まった金額 `A_i` を、券種ごとに次のように積み上げます。

| 券種 | 配分 |
|---|---|
| 単勝 X に `m` pt | `A_X += m` |
| 複勝 X に `m` pt | `A_X += a·m` |
| 三連単 X→Y→Z に `m` pt | `A_X += m/2`, `A_Y += m/3`, `A_Z += m/6` |
| 三連複 X,Y,Z に `m` pt | 3人それぞれ `+= m/3` |

重みが必ず `1/2+1/3+1/6 = 1`、`1/3×3 = 1` になっているので、
配分しても金額は増えも減りもしません。だから **`ΣA_i` がそのまま賭け金の総額**です。

```
T   = ΣA_i × (1 − 控除率)      払戻に回る総額
O_i = T ÷ A_i                  素オッズ
p_i = A_i ÷ ΣA_i               想定1着率（6人ぶん足すとちょうど1）
```

### 払戻

```
単勝   = 賭け金 × O_i
複勝   = 賭け金 × a × O_i
三連単 = 賭け金 × O_i × O_j × O_k          （単純積のとき）
三連複 = 賭け金 × O_i × O_j × O_k ÷ 6      （単純積のとき）
```

最後に `下限 〜 上限` に押し込んでから、丸め単位で切り上げます。

### 持ち点の繰越

```
開始pt   = 前レースの残高（無ければ初期持ち点）
残り     = 開始pt − 使用pt              ← まだ賭けられる額。購入はこれを超えられない
残高     = 開始pt − 使用pt + 払戻pt     ← 次のレースの開始pt
```

`「次のレースへ」を押したときに 残高 →（下限 = 敗者復活の最低持ち点）→ 次の開始pt` と流れます。

## 検証済みのこと

| 内容 | 結果 |
|---|---|
| 手書きの例（A100万 B50万 …）のオッズ | 2.50 / 5.00 / 6.25 / 10.00 / 12.50 / 16.67 と一致 |
| `Σ(1/O_i) = 1` | `1.000000000000`（0票の人はオッズ上限で頭打ちになるので、その人だけ例外） |
| `Σp_i = 1` | `1.000000000000`（0票の人が居ても成立） |
| Harville補正の期待払戻 | 全買い目で `1.000`（人気が偏った3ケースでも） |
| 単純積の期待払戻 | 横一線で `1.800`、偏ると `1.35〜3.09` に揺れる |
| 不正な購入（重複指名・持ち点オーバー・小数pt・締切後 など） | 9パターンすべて拒否 |
| 的中判定（単勝・複勝・三連単・三連複） | 全券種で正しく判定 |
| 10チームが150リクエスト同時 | 取りこぼし0件・持ち点オーバー0件・ID重複0件（453ms） |
| 運営ページで6人ぶん打ち込んで自動更新3回ぶん放置 | 消えない（未保存印が出ているフォームは自動更新が触らない） |
| 繰越（払戻を含む残高が次レースの持ち点になるか） | 1011pt繰越 → 次レースで1011pt購入OK、1012ptは拒否 |
| 着順なしで「次のレースへ」 | 繰り越さず持ち点据え置き（＝賭け金の返却） |
| 敗者復活の最低持ち点 | 全額溶かして0になったチームを100ptに戻す |
| 繰越が入る前の `race.json` を読み込み | 1レース目扱いで起動（全チーム初期持ち点） |

## 困ったとき

| 症状 | 対処 |
|---|---|
| スマホから開けない | 同じWi-Fiか確認。パソコンのファイアウォールでNodeを許可する |
| 起動時に `EADDRINUSE` | ポートが使用中。`PORT=3001 node server.js` |
| データを消してしまった | `data/archive/` に過去レースが残っています |
| `保存できませんでした` の警告 | ウイルス対策ソフトがファイルを掴んでいる。進行は続くので、終わる前に運営ページでCSVを書き出してください |
| **受付中と締切が数秒ごとに入れ替わる** | **Vercelに置いていてKVが未設定です。**「Vercel に置く場合」を参照して `KV_REST_API_URL` / `KV_REST_API_TOKEN` を設定し、再デプロイしてください |
| `他の端末の処理と重なりました` | 同時に購入が集中したときに出ます。もう一度押せば通ります（この表示が出たぶんは購入されていません） |
| 運営ページの上に赤帯が出ている | KVとの通信ができていません。その間の変更は他の端末に伝わらないので、先にこれを直してください |
| オッズを全部やり直したい | 運営ページ①進行「次のレースへ」（退避されるので消えません） |
| 持ち点が繰り越されていない | 着順を入れてから「次のレースへ」を押したか確認。①進行の「チームの持ち点」で手直しもできます |
| 繰越を無しにして毎レース同じ持ち点で始めたい | 毎レース①進行の「全部リセット」を押す（履歴も消えます） |

サーバを止めるのはターミナルで `Ctrl+C`。
購入内容は `data/race.json` に都度保存しているので、止めても消えません。
